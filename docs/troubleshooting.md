# Troubleshooting

Back to the [documentation index](README.md). Logs first: `%TEMP%\eq_asio_router_engine.log` (engine, rotated at about 1 MB, one old file kept). The tray GUI status panel and `router-cli run` show the same state live.

## Symptom, cause, fix

| Symptom | Cause | Fix |
|---|---|---|
| `Start failed: cannot open ASIO driver "Yamaha Steinberg USB ASIO": driver init failed (is another program using it?)` | The driver's `init` failed. Most often another process has the Yamaha open but holder detection found nothing (the check looks for the driver DLL in other processes), the interface was released a moment ago (the driver enforces a short cooldown and retries for about 2.5 s), or the interface is switched off or unplugged | Run `router-cli holders`; close VB Matrix, VirtualDJ, the VB ASIO Bridge or a DAW; check USB and power; press Start again. The tray app started at login retries by itself |
| `Waiting for Yamaha (in use by <program> (PID n))`, state `WaitingForDevice` | A listed process holds the Yamaha exclusively. The router retries every 2 s and starts as soon as it is free | Close that program, or stop its ASIO engine, or pick another device in it. "Retry now" skips the 2 s wait. The router never closes other programs by itself; the GUI offers an "Ask <exe> to close" button per holder that only posts a normal window-close request when you click it |
| Crackle or clicks | (0) On the VAC preset: an isolated click about every 30 s is the signature of a duplicated block at 5 ms (240 frames); use 6 ms (288 frames) and see the fallback row below. (a) Old builds: the drift controller was replaced; rebuild. (b) Exclusive capture: disabled because the Hi-Fi Cable driver corrupts it (30 to 70 % wrong samples at 3 to 5 ms); a config with `capture_mode = "exclusive"` is mapped to shared. (c) Rate mismatch in an app (next rows). (d) Ring underruns because the margin is too small or the Yamaha period too aggressive. (e) Another program loading the CPU or USB | Check the status: `underruns`, `gate_rearms`, `xrun`, `fault`. Raise `safety_buffer_ms` or run "Learn (30 s)"; keep `capture_mode = "shared"`; raise the Yamaha `PeriodFrames`; close CPU-heavy programs |
| Music sounds sped up, distorted or crackles; a player has "Exclusive mode" | An exclusive-mode stream on `Hi-Fi Cable Input` at a rate different from the cable format arrives unconverted (44.1 kHz data on a 48 kHz cable is 8.8 % too fast). Windows also blocks exclusive playback on the cable by default | Turn "Exclusive mode" off in the player and leave its output on `Hi-Fi Cable Input`. If it must stay on, set the player's rate to the cable's format (shown in the GUI) |
| Hardening row `MMCSS ASIO` shows FAILED (log: "mmcss ... asio FAILED") | Windows error 1552 (`ERROR_INVALID_TASK_INDEX`) means the thread already has an MMCSS registration: the Yamaha driver registers its own callback thread, so the router's second registration is refused. It is harmless: the thread already runs under "Pro Audio" | Nothing to do. `crates\router-engine\src\priority.rs` now counts 1552 as OK; the row turns green after you rebuild and restart the app. Any other error code is a real failure |
| Other hardening rows `FAILED` or `pending` | `pending` is normal until the first ASIO callback and the first capture packet. A real `FAILED` means Windows refused the call: `EcoQoS opt-out` or `Priority class` (process settings, policy may forbid), `1 ms timer` (`timeBeginPeriod` refused), `MMCSS control` / `MMCSS capture` (MMCSS service disabled or the "Pro Audio" task missing from the registry) | Check that the Multimedia Class Scheduler service is running. A failed row reduces robustness against Windows throttling; audio still works. Priority class is only raised when the process runs at Normal priority; a higher class chosen by you is left alone and counts as OK |
| Device missing at login (`Waiting for Hi-Fi Cable Output...` or `Waiting for ASIO driver ...`) | The cable or the Yamaha is not enumerated yet when the tray app starts | Nothing: the tray app retries with back-off (200 ms doubling to 5 s) until the device appears. If it never appears, check the device in Windows Sound settings and the Yamaha driver |
| Tray icon not visible | Windows hides new tray icons in the overflow ("^") | Drag it out of the overflow, or Settings > Personalization > Taskbar > Other system tray icons. Launching `eq-asio-app.exe` again shows the running window (single instance) |
| Cable shows 44100 Hz while the Yamaha runs 48000 Hz | Rate matching is off (the VAC preset turns it off, and it never touches VAC), failed, or the cable driver reverted the format | Audio still works (the resampler converts). To match: enable `match_cable_rate`, or "Set cable to Yamaha rate now" in the GUI, or set the format by hand in Sound > Recording > `Hi-Fi Cable Output` > Properties > Advanced. A failed attempt is not repeated for the same rate within 60 s |
| `another router engine instance is already running` (`AlreadyRunning`) | The tray app (or another `router-cli run`) already owns the engine mutex `Local\eq_asio_router_engine` | Use the running instance, or quit it (tray menu > Quit) before starting another. Rebuilding also needs the tray app closed |
| Second launch of the GUI does nothing visible | Single instance: it asked the first instance to show its window | Look in the tray; use the tray menu |
| `ASIO driver "X" is not registered` | The `master_driver` name does not match a registered ASIO driver | `router-cli devices` lists the names |
| `master driver "EQ ASIO Router" is not allowed` | That is the frozen v1 driver | Set `master_driver` to the Yamaha or leave it empty |
| `master has 1 output channel(s); at least 2 are required` / `output sample type N is not supported` | Unsuitable master | Choose another driver or `output_channels`; MSB sample types are not supported |
| Audio stops and the state shows `Restarting` with a reason | Self-healing: stalled callback (1 s) or capture (3 s), driver reset request, device lost | Read the reason and the log. Frequent restarts point at USB trouble, a busy cable or a failing driver |
| `config_error` in the status | `config.toml` does not parse; the last good config stays in force | Fix the TOML syntax; the engine reloads on save |
| Capture note: "Exclusive capture is disabled ..." | Expected: exclusive is mapped to shared | Use `shared` |
| Amber banner "Capture fell back to Shared (10 ms): <reason>" (status `capture_fallback`; `router-cli run` prints `WARNING:`) | VAC Line 1 only. The corruption monitor saw damaged data from the fixed-period capture (frames faster than real time, repeated identical blocks, or sustained packet anomalies), so the router reopened the capture once in plain Shared. Audio keeps working at about 10 ms packets, i.e. higher latency. It is not retried by itself and does not loop | Press "Retry fixed period" (restarts the stream), or change the capture period or device, which re-arms it. Use a period of 6 ms or more (288 frames; 5 ms was unreliable). If it repeats, stay on Shared or use the Hi-Fi Cable preset and keep the reason text and the log. Hardware validation of this path is still pending, so a first fallback is useful information |
| `Waiting for Line 1 (Virtual Audio Cable)...` | The Line 1 recording endpoint is not active (on the author's machine it was inactive once and became active later without a known trigger). The engine retries with back-off | Windows Sound control panel > Recording > right-click the empty area > Show Disabled Devices > right-click "Line 1" > Enable. The "Open Windows Sound settings" button in the Source section opens the Windows Sound page; the app changes nothing itself |
| Source readiness note: Set Line 1 as the Windows default playback device (or silence on the VAC source, peaks at -inf) | Windows default playback is not Line 1, so nothing plays into the cable | Settings > System > Sound > Output > Line 1, or Sound control panel > Playback > Set as Default Device. The router never changes the default device |
| Readiness note "Cable formats differ or are not stereo (capture X Hz/n ch, playback Y Hz/m ch)" | The two Line 1 endpoints have different formats (VAC lite supports 48 kHz, 16 bit, stereo only) | Set both to the same 48000 Hz format in Windows Sound > Properties > Advanced. The router never changes a VAC format |
| `Render keep-alive not started: ...`, `Render keep-alive skipped: "<name>" is not a known virtual cable.` or `Render keep-alive stopped: its render endpoint was lost.` | The keep-alive is non-fatal. Not started: the render endpoint could not be opened; skipped: the capture device is not a virtual cable (it is never run on real outputs); stopped: the endpoint disappeared | Audio is unaffected, only the render-side latency benefit is lost. Check that the Line 1 playback endpoint is active, then press Restart. Turn the keep-alive off in the Source section if it keeps failing |
| Note "capture period X ms is ignored: ... is not a known virtual cable" or "capture_period_ms is ignored in LowLatency mode" | A fixed period only applies to Shared capture of a virtual cable endpoint | Pick the VAC or Hi-Fi Cable preset, or set `capture_mode = "shared"` and a virtual-cable `capture_device` |
| `capture_mode = "lowlatency"` on VAC fails or falls back with "IAudioClient3 minimum period ... is below 2.5 ms" | VAC lite advertises a 1 ms minimum but corrupts audio below 5 ms; the capture layer refuses that period | Use the VAC preset (fixed 6 ms) instead; never set `lowlatency` for VAC |
| Switching the preset in the GUI shows a dialog "Switch source preset?" | One-time confirmation: a preset changes the capture device, period, keep-alive and cable-rate matching and restarts the engine (1-2 s) | Press Switch. It is remembered as `preset_confirmed` in `app_settings.toml`; delete that line (or set it to false) to see it again |
| Silence, state Running, peaks at -inf | Nothing plays into the cable, or Windows default playback is not `Hi-Fi Cable Input` | Check the default playback device and app volume. The ring still runs; the capture-silent counter rises |

## Log locations

| File | Content |
|---|---|
| `%TEMP%\eq_asio_router_engine.log` | Engine: start, hardening summary, capture mode and period, capture fallback / corruption reasons, render keep-alive start (engine period before and after), restarts and reasons, waiting-for-device, learn results |
| `%TEMP%\eq_asio_router_driver.log` | Only the frozen v1 virtual driver (not used any more) |
| `%APPDATA%\eq_asio_router\caps.toml` | What the master reported at the last start |

## Reverting changes

| Change | How to revert |
|---|---|
| Cable format changed by the router | Sound settings > cable endpoint > Properties > Advanced > previous format (the status line shows the old rate). Prevent it with `match_cable_rate = false` |
| Run at login | Untick "Run at login" in the GUI, or delete the value `EQ ASIO Router` under `HKCU\Software\Microsoft\Windows\CurrentVersion\Run` |
| Yamaha latency settings | Yamaha control panel: set Mode to Standard and Buffer Size back (the original values on the author's machine were 512 and Standard, before tuning); the router does not write these registry values itself |
| EQ profile | Bypass in the GUI, or delete the `[profile]` section of `config.toml` |
| Source preset (VAC Line 1 back to the Hi-Fi Cable) | Choose "Hi-Fi Cable (compat)" in the Source section (or `router-cli run --source cable`), then set Windows default playback back to `Hi-Fi Cable Input`. The router never changed the Windows default itself |
| All router settings | Close the app, delete `%APPDATA%\eq_asio_router\` (the router recreates defaults) |
| Frozen v1 driver (only if you ever installed it) | `scripts\uninstall-driver.ps1` (self-elevating) |
